公開ページ：https://toratorasuienten.info/sheeshastoresimulator/
運営：ミツメディア（info@mitsumedia.xyz）

このフォルダは**作業用**です。遊ぶ人に届くのはリポジトリ直下の `index.html` と `version.txt` の2つだけです。

## 1. 仕組み

```
dev/
  VERSION          … 今のバージョン（1行）。公開のたびに上げる
  src/             … ゲームの元ファイル
    shell.html     … HTMLの外枠（CSSや画面の部品）。中に /*@@ファイル名@@*/ の目印がある
    order.json     … つなげる順番
    00〜03_*.js    … 広告・エラー表示・QRライブラリ・文字表示の小さなスクリプト
    10〜26_*.js    … ゲーム本体（下の一覧）
  tools/build.py   … src をつなげて index.html を作る
  tools/split.py   … 最初に完成品を分けたときの道具（ふだんは使わない）
  tests/           … 自動テスト（Playwright）
  history/         … 整理前の「上書き部品」184個の保管（v1.0.0〜1.0.158）
```

### 作り方
```
python3 dev/tools/build.py        # リポジトリ直下の index.html と version.txt を作り直す
```
`dev/VERSION` の番号が、ゲームの中の表示（`GVER` と「Ver ○○」）にも入ります。

### 直すときのルール
- 直したい機能が書いてあるファイルを、直接書き換える
- 多くの機能は「前の関数を包んで（wrap して）上書きする」作りになっている。**包む側は、包まれる側より後ろのファイルに置く**
- 新しい機能は、新しいファイル（例：`27_○○.js`）を作って `order.json` の最後に足すのがいちばん安全。build.py が自動で前のファイルの後ろにつなげる
- 順番を入れ替えると動きが変わるので、ファイルの並べ替えはしない

## 3. 公開の手順
1. `dev/VERSION` を1つ上げる（例：1.0.158 → 1.0.159）
2. `python3 dev/tools/build.py`
3. テストを動かす
4. コミットして push（作者：mitsumedia / info@mitsumedia.xyz）
5. 運営者に「管理ページで『最新版に更新』を**2回**押してください」と伝える
   - サーバーの api.php が GitHub から `index.html` と `version.txt` を取ってきて置き換える仕組み

## 4. サーバー（このリポジトリには入れない）
- `api.php`・`.htaccess`・`ads.txt`・規約ページなどは、運営者が Lolipop の FTP で直接アップロードする
- **`config.php`（DB接続・管理パスワード）は絶対にリポジトリに入れない・公開しない**
- パスワード類はチャットにも書かない・打ち込まない

## 5. 運営者とのやり取りのルール
- 返事は日本語・短めに（スマホで読んでいる）
- **実装する前に、内容を確認してから進める**
- 「指示モード」→ 実装せず内容の確認だけ／「メモモード」→ 実装せずタスクとして記録
- 着せ替えアイテムを増やすときは、どの欄（スロット）を使い、ほかのアイテムとどう組み合わさるかを先に確認する
- GitHub の操作は運営者ではなくこちらで行う

## 6. 保留中・これから
- 看板（店の外に置く）：保留
- 営業時間の固定、ガチャのコンプ報酬、バトルミニゲームの置き換え：保留
- 家具の「シリーズ」（例：和風シリーズ。既存の鯉の池なども含めて1シリーズ10個）：ユーザーが「◯◯シリーズで10個作って」と順に指示する予定
- お客さんからもらえる非売品は一旦リセット（シーシャ屋の客からもらえる物はそのまま）。**全シリーズの家具がそろって、プレゼントの振り分けが決まってから実装する**
- 特殊な出店場所：リアル寄りの案10個（路地裏・高級住宅街・ロードサイド・河川敷・SA・団地・工場地帯・モール・公園・オフィス街）を出して、選んでもらう途中
